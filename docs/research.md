# Partial kits and shift changes defeat checkout tools

Seventeen checkout, asset, rental and library products all handle the basic loan well: barcode checkout, a due date, an overdue alert and an item history. Almost all of them break down at the same three points a campus media desk hits every day. The first is a kit that comes back incomplete. The second is a camera returned by a teammate rather than the borrower. The third is a shift change, when open problems pass to a new student worker. Partial returns are shown clearly only where the loan has a container (a booking, order or project), as in Shelf's "Partial return · N still out" receipt and Booqable's "Mixed" order status. Per-item asset tools such as Snipe-IT treat a kit as a checkout template that disappears once the gear leaves the desk. No product records "the person holding this item is not the borrower" on a short loan. None documents a shift handover log. Undo is almost absent: only Booqable's status revert and EZOfficeInventory's stock-history "x" are documented. Healthcare evidence fills these gaps with tested patterns. Barcode verification at the point of action cut drug administration errors by about 41%, and the I-PASS structured handoff bundle cut medical errors by 23% without lengthening handoffs. A desk prototype should therefore put four things first: a kit-level remainder view, explicit holder custody, confirm-by-scan check-in with a time-boxed undo, and loan-attached handover items. Each of these can be measured at a real counter with before-and-after counts of wrong-unit returns, kit parts discovered missing later, and open loans dropped at shift change.

## Partial returns stay visible only when the loan has a container

The clearest split across the market is structural. Rental and booking tools keep an order or booking as a container, so a half-returned kit has a visible state. Asset tools record the loan per item, so a kit stops existing as a returnable unit after checkout. **Shelf** has the richest remainder model. A segmented "Check-in progress" bar uses grey, amber, purple and green states. Each returned asset carries an "Already checked in" label, and a printable receipt is stamped **"Partial return · N still out"** until the last unit is back. An owner setting, "Count each kit as a single unit", stops a 32-asset kit from inflating totals ([Shelf](https://shelf.nu/knowledge-base/partial-check-ins-efficiently-handle-incomplete-returns)). **Booqable** added a **"Mixed" order status** in May 2021 for partly picked-up or returned orders, and it refuses to let items go out on a new order until they are returned on the old one ([Booqable](https://booqable.com/whats-new/may_03_2021/); [Booqable workflow](https://help.booqable.com/en/articles/3845244-the-booqable-order-workflow)). **Rentman** validates scanned returns against the project's packing list. Its "Check and refill" option for cases forces an item-by-item scan, and its own best practice is to accept a sealed case as complete only after visually confirming it ([Rentman](https://support.rentman.io/hc/en-us/articles/27954393425042-Scan-Return-with-Rentman-Mobile-App); [Rentman best practices](https://support.rentman.io/hc/en-us/articles/36232279237010-Best-Practices-How-to-Process-Equipment-Returns-Efficiently)).

The dedicated checkout tools sit between these two models. **Cheqroom** keeps a check-out "open" after a partial check-in, with returned items made available again. Its desktop-only Quick Check-in shows a scanned count for each check-out and a green tick when everything is in, but it has no labelled "partial" status ([Cheqroom check-outs](https://knowledge.cheqroom.com/helpcenter/how-to-create-and-manage-check-outs-and-check-ins); [Cheqroom Quick check-in](https://knowledge.cheqroom.com/helpcenter/quick-check-in)). **WebCheckout**, which markets itself to film schools, is documented mainly through university guides. Carleton staff check kit contents ("SD cards, batteries, and cables") by eye, then choose "Return All" or "Return Selected" ([Carleton](https://stolafcarleton.teamdynamix.com/TDClient/2092/Carleton/KB/Article/164362/Returning-Equipment-in-Webcheckout)). **Lend Engine** turns each kit component into its own loan line, which can be checked in "at separate times, or all at once" ([Lend Engine guide](https://www.lend-engine.com/downloads/LendEngineUserGuide2020.2.pdf)). That makes it the only library-of-things tool that knows *which* part is still out.

Asset tools fare worst. **Snipe-IT's predefined kits are built from asset models, not specific units**, and there is no kit check-in. Requests for kits made of specific assets have been open since 2020 ([#8539](https://github.com/grokability/snipe-it/issues/8539); [#10495](https://github.com/grokability/snipe-it/issues/10495)). One user describes "a good half hour of repetitive clicking" to hand over a camera bag ([#9517](https://github.com/grokability/snipe-it/issues/9517)), and as of October 2026 there is still no count of how many complete kits are available ([#19888](https://github.com/grokability/snipe-it/issues/19888)). **Asset Panda** goes the other way: kit assets "will always be returned together" ([Asset Panda](https://help.assetpanda.com/Kits.html)), so a partial return is not a native concept. **Sortly** has no loan at all. Checkout means moving quantities between folders ([Sortly](https://help.sortly.com/hc/en-us/articles/360002026312-How-to-Check-Out-or-Move-Items-Using-Sortly)).

Library systems treat a multi-part item as one barcode plus a text note. **Koha** comes closest to a hard stop. When "Materials specified" is filled and CircConfirmItemParts is set to "Require", staff must answer "Please confirm that the accompanying materials are present" with "Yes, check in" or "No, don't check in" ([Koha manual](https://koha-community.org/manual/latest/en/html/circulation.html)). **Alma's Pieces field triggers no pop-up**, so libraries hand-write a fulfillment note reading "Item consists of ___ pieces" ([Princeton](https://pul-confluence.atlassian.net/wiki/spaces/ALMA/pages/1770134/Fulfillment+Notes+and+Pieces+Count)). Procedure says incomplete items "should not be discharged" and go to a supervisor ([Vanderbilt](https://docs.library.vanderbilt.edu/2019/03/20/return-items/)). **Polaris alone has a missing-part state**. "Claim Missing Parts" blocks circulation and notifies the current or last borrower ([Polaris](https://documentation.iii.com/polaris/7.0/PolarisStaffHelp/Patron_Services/PPckin/Check-in%20items%20with%20missing%20parts.htm)). The lesson is that a yes/no prompt on free text guards the moment of return, but only a per-component record shows the next shift what is still missing.

## Every product tracks the borrower of record, not the person holding the gear

Custody exists as a word in several products, but it means long-term assignment, not a teammate holding a camera mid-loan. **Cheqroom defines custody as "a check-out without a specified due date"** ([Cheqroom](https://knowledge.cheqroom.com/helpcenter/standard-check-outs-vs.-long-term-custody)). Its only short-loan option is editing the check-out's contact, which overwrites the original borrower rather than recording a handover ([Cheqroom check-outs](https://knowledge.cheqroom.com/helpcenter/how-to-create-and-manage-check-outs-and-check-ins)). **Shelf explicitly refuses** to give custody of a checked-out asset. Its August 2026 update ranks "Checked out" above "In custody", after a bug where custody hid checkouts and overstated availability ([Shelf update](https://www.shelf.nu/updates/custody-never-hides-a-checkout)). EZOfficeInventory lets staff transfer custody by scanning a label ([EZO mobile app](https://www.ezofficeinventory.com/mobile-app)), and Snipe-IT can check out to a user, location or asset, but reassigning means checking in and out again ([Snipe-IT docs](https://snipe-it.readme.io/docs/overview)).

Libraries make the borrower-of-record rule explicit by design. Koha check-in is keyed on the item barcode, so whoever drops the item off, the loan clears ([Koha manual](https://koha-community.org/manual/latest/en/html/circulation.html)). A missing part found later is pinned on the borrower, as Polaris's notice routing shows ([Polaris](https://documentation.iii.com/polaris/7.0/PolarisStaffHelp/Patron_Services/PPckin/Check-in%20items%20with%20missing%20parts.htm)). UW-Madison's WebCheckout policy goes further. Items left at the wrong location "are not considered returned" and keep accruing fines on the borrower ([UW InfoLabs](https://kb.wisc.edu/page.php?id=131963)). I found no source in which any system records the identity of a third-party returner. For a film desk, where crews swap gear constantly, this is the most open gap. Borrower liability can stay as it is, while the system also logs who physically handed the item over and when.

## Overdue tracking is solved, but escalation lives in campus policy

Every product except Sortly has native overdue handling. Cheqroom has configurable "Check-out due" notifications and a push alert at one hour overdue ([Cheqroom](https://help.cheqroom.com/articles/1865415-mobile-push-notifications)). EZOfficeInventory emails the borrower on the day an item becomes overdue and offers a "Check in Overdue" filter ([EZO FAQ](https://ezo.io/ezofficeinventory/faqs/what-happens-if-an-asset-becomes-overdue/)). Reftab's "Maximum Overdue Limit" blocks further checkouts ([Reftab FAQ](https://www.reftab.com/faq/reftab-reservation-and-checkout-settings-faq)). itemit alerts the borrower's manager ([itemit](https://itemit.com/asset-tracking/equipment-checkout-software)). Snipe-IT runs a cron job that by default notifies only the admin, until a later setting added the user ([PR #14655](https://www.github.com/snipe/snipe-it/pull/14655)). Koha adds a fine grace period, book-drop backdating and a "Forgive overdue charges" box at check-in ([Koha administration](https://koha-community.org/manual/latest/en/html/administration.html)). The penalties themselves are set by universities. UW-Madison applies a **10-day hold after one day overdue and a 30-day hold after ten days** ([UW InfoLabs](https://kb.wisc.edu/page.php?id=131963)), and Michigan LSA uses strikes that lead to an account freeze ([UMich](https://teamdynamix.umich.edu/TDClient/47/LSAPortal/KB/ArticleDet?ID=15191)).

One signal is worth copying. myTurn's July 2026 dashboard counts **"overdue items needed for upcoming reservations"** ([myTurn](https://myturn.com/?p=7606)), which ranks overdue loans by their effect on the next booking rather than by days late. For a desk that lends a few cinema cameras against a waitlist, this is the overdue view that matters during a shift. A prototype does not need to rebuild alerts. It should rank and hand over the overdue loans that block someone else.

## Scanning is the default everywhere and required almost nowhere

Every product supports barcode check-in, but nearly all of them let staff skip it. Cheqroom accepts ticked checkboxes. It guards against a stray unit only by putting scanned items that are not on any check-out under "Unexpected Items" ([Cheqroom Quick check-in](https://knowledge.cheqroom.com/helpcenter/quick-check-in)). **Shelf is the only product that documents an owner setting forcing the scanner flow** ([Shelf](https://shelf.nu/knowledge-base/partial-check-ins-efficiently-handle-incomplete-returns)). Snipe-IT's "Quickscan Checkin" page sits next to an ordinary click-to-check-in button ([Snipe-IT routes](https://raw.githubusercontent.com/grokability/snipe-it/master/routes/web/hardware.php)). Booqable allows selecting items by scan "or choosing the product or stock item manually" ([Booqable](https://help.booqable.com/en/articles/3845244-the-booqable-order-workflow)). Koha's own manual warns that checking in from the patron's list without scanning can lead to selection errors ([Koha manual](https://koha-community.org/manual/latest/en/html/circulation.html)). This is the only vendor statement found that names scanning as the accuracy safeguard. Sub-parts without barcodes, such as batteries and cards, are still counted by eye at every desk studied.

Healthcare puts numbers on what this optionality costs. In Poon and colleagues' NEJM study of 14,041 observed medication administrations, bedside barcode verification cut **non-timing administration errors from 11.5% to 6.8%, a 41% relative reduction**, and potential adverse drug events by about 51%. It "did not eliminate such errors" ([Poon et al.](https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=EXT_ID:20445181%20AND%20SRC:MED&resultType=core&format=json)). Koppel and colleagues explain why. Nurses overrode alerts for **10.3% of medications**, and workarounds included taping barcodes to carts and pre-scanning batches, often because barcodes were unreadable or scanners failed ([Koppel et al.](https://psnet.ahrq.gov/issue/workarounds-barcode-medication-administration-systems-their-occurrences-causes-and-threats)). AHRQ's mistake-proofing guidance prefers design constraints over training and warning labels ([AHRQ](https://webarchive.library.unt.edu/eot2008/20081104224438/http:/www.ahrq.gov/qual/mistakeproof/mistake1.htm)). For a desk, this means "confirm by ID" (scan or type the tag, which must match the loan) is a real poka-yoke, while "click to confirm" only checks intent. The verification step must also be faster than skipping it, with no master barcode sheet taped to the counter and with logged override reasons. The evidence is clinical and before-after, not randomised, and no study measures barcode verification at a lending desk. The direction is clear, but the size of the effect at a desk is unknown.

## Audit logs are universal, undo is nearly absent, and handover is unmodelled

Every product keeps a per-item or per-transaction history: itemit's chain of custody, EZOfficeInventory's Item Trail, Shelf's booking activity log, Asset Panda's Checkout Logs, and FOLIO's circulation log ([itemit](https://itemit.com/asset-tracking/equipment-checkout-software); [EZO Item Trail](https://blog.ezofficeinventory.com/item-trail/); [FOLIO](https://docs.folio.org/docs/access/check-in/checkin)). Logging partial kits is fragile, though. Until June 2026, Shelf wrote an empty entry, "performed a partial check-out: .", for partial kit checkouts ([Shelf update](https://www.shelf.nu/updates/partial-kit-checkout-activity-note)). Undo is rarer. **Booqable lets staff revert an order status "at any time to fix mistakes"**, restricted by permissions, and EZOfficeInventory undoes stock actions with an "x" in Stock History ([Booqable](https://help.booqable.com/en/articles/3845244-the-booqable-order-workflow); [EZO FAQ](https://ezo.io/ezofficeinventory/faqs/is-there-a-way-to-undo-a-sale-logged-by-mistake/)). Nothing else documents reversing a mistaken check-in. In practice the fix is a compensating re-checkout that leaves no "this was an error" marker. HCI guidance says this is the wrong trade. Nielsen finds that routine confirmations are clicked through out of habit and should be kept for severe, irreversible actions, named specifically, and paired with undo ([NN/g](https://www.nngroup.com/articles/confirmation-dialog/)). Aza Raskin puts it as "Never use a warning when you mean undo" ([A List Apart](https://alistapart.com/article/neveruseawarning)). This guidance comes from experts and usability observation, not controlled trials.

**No product documents a shift handover or desk log.** Notes attach to transactions instead: Reftab loan notes, Cheqroom check-in comments, Koha checkout notes that "appear during check-in", and Alma fulfillment notes that pop up on loan and return ([Reftab](https://www.reftab.com/blog/loans); [Koha manual](https://koha-community.org/manual/latest/en/html/circulation.html); [Princeton](https://pul-confluence.atlassian.net/wiki/spaces/ALMA/pages/1770134/Fulfillment+Notes+and+Pieces+Count)). The library pattern, a message attached to the object that will be scanned next, is useful because it fires at the moment of action. It cannot answer the question a new shift asks: what is open, and what do I owe it?

Healthcare has tested answers to that question. **I-PASS** (illness severity, patient summary, action list, situation awareness with contingencies, and synthesis by the receiver) was introduced as a bundle across nine hospitals and 10,740 admissions. It **cut medical errors 23%, from 24.5 to 18.8 per 100 admissions, and preventable adverse events 30%**, with no significant change in oral handoff duration ([Starmer et al.](https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=EXT_ID:25372088%20AND%20SRC:MED&resultType=core&format=json)). The effect belongs to the bundle of format, training and reinforcement, not to the mnemonic alone. SBAR's evidence is weaker. Only 8 of 26 outcomes improved across 11 studies, and the benefit was strongest for structured phone calls ([Müller et al.](https://pmc.ncbi.nlm.nih.gov/articles/PMC6112409)). Record-linked sign-out also helps. In a randomised crossover trial, a sign-out system that pulled data from the record halved patients missed on rounds, from 5 to 2.5 per team per month ([Van Eaton et al.](https://psnet.ahrq.gov/issue/randomized-controlled-trial-evaluating-impact-computerized-rounding-and-sign-out-system)). Emergency handoffs omitted information **45.1%** of the time, and less often when written support was used ([AJEM](https://ajemjournal.com/article/S0735-67570900626-3/fulltext)). Applied to a loan desk, I-PASS becomes one handover row per open loan. Each row carries a severity flag (overdue, due this shift, fine), a loan summary, an action with a named owner, an if-then contingency such as "if not back by 5, call X", and a receiver read-back. Rows should be generated from the loan records, not retyped into a free-text log.

## Four gaps a campus media desk prototype should close first

The matrix shows where the market has gaps and where a prototype can add something that existing tools lack. **The first priority is a kit-level remainder that names the missing part**: Shelf's "N still out" combined with Lend Engine's per-component lines and Polaris's blocking missing-part state. The current owner of the gap should be visible to the next shift as well as to the borrower. **The second is explicit holder custody on short loans.** Keep the borrower of record liable, as every library does, but add a "held by" or "returned by" field with a timestamp. Shelf's 2026 custody bug is a warning to keep a strict status priority. **The third is confirm-by-scan check-in with a time-boxed undo instead of an "Are you sure?" dialog.** The scan must match the loan's specific serial, mismatches go to an "unexpected item" lane as in Cheqroom, overrides require a logged reason as Koppel's findings suggest, and an undo window is marked in the audit log as a correction. **The fourth is an I-PASS-style handover list built from open loans**, with severity, action owner, contingency and receiver acknowledgement, ranked by the myTurn signal of which overdue items block upcoming reservations. Overdue alerts and penalty logic are already solved and set by campus policy, so a prototype should integrate with them rather than rebuild them.

The case against this list deserves a hearing. Strict scanning slows a busy counter, and Cheqroom's own help warns that friction-adding states (draft check-outs that block items) need regular cleanup ([Cheqroom](https://knowledge.cheqroom.com/helpcenter/how-to-create-and-manage-check-outs-and-check-ins)). Per-component barcoding, the Lend Engine trade-off, means labelling every battery and card. A sensible middle path is to barcode high-value or often-lost parts and use a count prompt in the Koha style for the rest. I-PASS's unchanged handoff duration suggests that structure does not have to cost time. This needs to be checked at the desk, not assumed.

## Observable metrics for testing at a real counter

The healthcare studies give a usable measurement template. Both I-PASS and the Poon barcode study used before-and-after designs with a baseline period, direct observation and system logs ([Starmer et al.](https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=EXT_ID:25372088%20AND%20SRC:MED&resultType=core&format=json); [Poon et al.](https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=EXT_ID:20445181%20AND%20SRC:MED&resultType=core&format=json)). A desk can copy that design with two to four weeks of baseline on the current system, then the same period on the prototype, counted per 100 transactions. The metrics below adapt validated clinical measures. None has been validated at a lending desk, so treat them as proposed.

| Metric | What to count | Clinical analog |
|---|---|---|
| Wrong-unit check-ins | Returns where the scanned or recorded serial did not match the loan, per 100 check-ins | Poon administration error rate |
| Late-discovered missing parts | Kit components found missing after the kit was marked returned | Van Eaton "patients missed on rounds" |
| Override rate and reasons | Check-ins completed without a matching scan, with the logged reason | Koppel override logs (10.3% of medications) |
| Correction events | Undo uses and compensating re-checkouts, and time from error to correction | Undo vs confirmation guidance (NN/g) |
| Handover omissions | Open loans or partial kits missing from the handover, or with no owner or next action | ED handoff omissions (45.1%), I-PASS key-element inclusion |
| Handover duration | Minutes per shift change, observed | I-PASS oral handoff duration |
| Call-backs to previous shift | Messages to the outgoing worker within N hours asking about an open loan | Receiver clarifying questions (not a validated outcome) |
| Time to resolve handed-over items | Hours from handover to closing an overdue chase or missing-part claim | I-PASS action list follow-through |
| Check-in time per item | Seconds from item on counter to loan cleared, so the verification cost is visible | I-PASS workflow time-motion |
| Holder mismatches recorded | Returns logged with a returner different from the borrower | No analog; new to this domain |

Two cautions apply. Counting needs a neutral observer for at least part of the trial, because student workers who know the target will under-report their own slips. Also report check-in time alongside error rates, since Koppel's workarounds appeared exactly where verification cost more than skipping it.

## Conclusion

The review changes the main design question for a media desk. Existing tools treat a loan as one borrower plus one item, and they bolt kits on as checkout shortcuts. The real unit of work at a busy counter is the open obligation: a missing battery, a camera with the wrong student, an overdue lens blocking tomorrow's shoot. That obligation has to survive a shift change. The products that come closest (Shelf, Booqable, Lend Engine, Polaris) each solve one part of it, and none connects that state to the person who takes over the desk next.

That makes the prototype's advantage narrow and testable, not a broad rebuild. Pair the one strong error-proofing result (scan verification works, and its workarounds are predictable) with the one strong handover result (structured bundles reduce errors without slowing handoffs), attach both to the open loan record, and measure wrong-unit returns, late-discovered missing parts and handover omissions against a baseline. If those three numbers do not move at a real counter, more features will not help.
